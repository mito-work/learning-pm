# スコープ管理 > 立ち上げ

## 超概算：【対客】接続機器（対象デバイス／ブラウザ等）の確認

---

## 導入

### このスキルを身につけると、何が変わるか

「スマホでも使えるようにしてほしい」
その一言が、後から工数を大きく変えることがあります。

- PCだけのつもりで設計したのに、スマホ対応が追加された
- 「古いIEでも動くように」という要件が直前に発覚した
- 工場のハンディターミナルでも使いたいと言われた

接続機器（デバイス）やブラウザの確認は、
「どうせPCでしょ」と決めつけがちな落とし穴です。
超概算フェーズで確認しておくことで：

- デバイス対応によるコスト増を早期に把握できる
- 「対応できません」ではなく「コストが○円変わります」と説明できる
- 後からの要件追加によるスコープクリープを防げる

---

## 学習目標

このテキストを読み終えると、以下ができるようになります。

1. **対象デバイス・ブラウザの種類が見積もりに与える影響を説明できる**
2. **顧客から対象デバイスと利用環境を引き出す問いかけができる**
3. **デバイス・ブラウザ要件を超概算の前提条件として整理できる**

## 本編

---

### Section 1：なぜデバイス・ブラウザの確認が重要か

**一言でいうと：対応するデバイスが増えるほど、開発・テストのコストが増えるからです。**

料理で考えてみましょう。
「夕食を1品作る」のと「夕食・弁当・離乳食・アレルギー対応を全部作る」のでは、
手間がまったく異なります。同じ「ご飯を作る」でも、対象が増えると工数は跳ね上がります。

システム開発も同じです。
「PCのChromeで使える」ものを作るのと、
「スマホ・タブレット・PC、複数ブラウザすべてで使える」ものを作るのは、
設計から開発・テストまで、かかる工数がまったく違います。

**デバイスが増えると増える作業：**

| 増える作業 | 内容 |
|---------|------|
| デザイン | 画面サイズごとにレイアウトを設計する |
| 実装 | デバイスごとの表示・動作を作り分ける |
| テスト | デバイス×ブラウザの組み合わせを検証する |
| 保守 | OS・ブラウザのアップデートへの追従 |

超概算の段階で対象を絞り込むことで、見積もりの精度が上がります。

---

### Section 2：確認すべきデバイスの種類

**一言でいうと：「どこで、誰が、何を使って操作するか」をイメージして確認する。**

デバイスは大きく以下の5種類に分けて考えます。

| デバイス種別 | 代表例 | 確認ポイント |
|-----------|------|-----------|
| **PCブラウザ** | Windows・Mac上のChrome・Edge・Safari | 対応ブラウザの種類・バージョン |
| **スマートフォン** | iPhone（Safari）・Android（Chrome） | iOS・Androidどちらか、両方か |
| **タブレット** | iPad・Androidタブレット | 縦横対応が必要か |
| **専用ハードウェア** | ハンディターミナル・POS端末・バーコードリーダー | 機種・OS・画面サイズ |
| **その他** | 大型モニター（サイネージ）・スマートTV | 解像度・操作方法 |

多くの業務システムはPCブラウザだけで十分ですが、
現場系・店舗系・物流系のシステムでは専用ハードウェアが登場することがあります。

---

### Section 3：ブラウザ要件の確認

**一言でいうと：特にIE（Internet Explorer）の要否が、コストに大きく影響する。**

ブラウザには種類があり、それぞれ動作が異なります。

| ブラウザ | 特徴 | 注意点 |
|--------|------|------|
| **Chrome** | シェア最大・最新技術対応 | 事実上の標準 |
| **Edge** | Windows標準・Chrome互換 | ChromeベースになりChrome対応と近い |
| **Safari** | iPhone・Mac標準 | iOS対応には必須 |
| **Firefox** | 技術者に人気 | 要件による |
| **IE（Internet Explorer）** | 旧式・2022年サポート終了 | **対応コストが大幅増** |

**IEは特別に確認が必要です。**

IEはMicrosoft社がサポートを終了しており、
現代のWebシステムでは通常サポート対象外です。
しかし、古い社内システムを使い続けている企業では、
「IEでしか動かない環境」が残っているケースがあります。

IEへの対応が必要になると：
- 最新のデザイン手法が使えない
- 開発・テストの工数が大幅に増える
- 場合によってはシステム設計を根本から見直す必要がある

```
確認の問いかけ：
「現在の社内ルールで、使用しなければならないブラウザはありますか？」
「IE（Internet Explorer）の利用は残っていますか？」
```

---

### Section 4：利用環境の確認の進め方

**一言でいうと：「誰が・どこで・どんな環境で使うか」を場面ごとに聞く。**

デバイスを確認するには、「利用シーン」から逆算するのが効果的です。

#### ① 利用者と利用場所を確認する

```
使える質問：
「このシステムは、主にどんな方が使いますか？」
「オフィスで使いますか？それとも現場・外出先・店舗でも使いますか？」
「自宅からアクセスする必要はありますか？」
```

利用場所が変わると、必要なデバイスが変わります。

| 利用場所 | 想定されるデバイス |
|--------|---------------|
| オフィスのみ | PCブラウザ（社内ネットワーク） |
| 外出先・移動中 | スマートフォン・タブレット |
| 工場・倉庫 | ハンディターミナル・タブレット |
| 店舗 | POS端末・タブレット・PC |
| 自宅（テレワーク） | 個人PC（ブラウザ種類が多様化） |

#### ② 社内の端末環境を確認する

```
使える質問：
「社員の方は、どんな端末（PC・スマホ・タブレット）を使っていますか？」
「会社支給の端末ですか？それとも個人端末（BYOD）も使いますか？」
「社内のPC環境は統一されていますか？（Windows・Mac・バージョンなど）」
```

社内端末が統一されている場合は、対応範囲を絞れるため工数が下がります。
個人端末（BYOD）を許可している場合は、OSやブラウザの組み合わせが多様になり、テスト工数が増えます。

#### ③ 専用ハードウェアの有無を確認する

```
使える質問：
「バーコードリーダーやハンディターミナルなど、
 特殊な機器を使う予定はありますか？」
「POS端末や専用の業務機器と連動させる必要はありますか？」
```

専用ハードウェアが出てきた場合は、機種名・OS・画面サイズ・操作方法まで確認します。
ハードウェアメーカーの制約が開発に影響することがあるためです。

---

### Section 5：対応範囲の決め方と工数への影響

**一言でいうと：「対応するデバイス×ブラウザの組み合わせ数」が工数を決める。**

対応範囲を決めるときは、「組み合わせ数」で考えます。

**例：PCブラウザのみの場合**
```
Chrome最新版・Edge最新版 の2種類 → テスト項目：小
```

**例：PC＋スマホ対応の場合**
```
PC：Chrome・Edge
スマホ：iOS Safari・Android Chrome
→ テスト組み合わせ：4種類、レスポンシブ対応が必要 → テスト項目：中
```

**例：PC＋スマホ＋IE対応の場合**
```
上記に加えてIE11
→ IE専用の実装が必要 → テスト項目：大幅増
→ 開発工数：30〜50%増になることもある
```

`レスポンシブデザイン：PCとスマホなど画面サイズの違いに合わせて、自動でレイアウトを切り替える設計手法のこと。`

---

### Section 6：確認結果の記録方法

**一言でいうと：対象デバイス・ブラウザ・OS・バージョンを一覧にして前提条件として残す。**

**デバイス・ブラウザ確認シート（超概算時点）：**

```
■ 対象デバイス・ブラウザ一覧（20XX年XX月XX日時点）

【対応デバイス】
  ✅ PC（Windows）
  ✅ PC（Mac）
  ✅ スマートフォン（iOS）
  ✅ スマートフォン（Android）
  ❌ タブレット（今回は対象外）
  ❌ ハンディターミナル（今回は対象外）

【対応ブラウザ】
  ✅ Google Chrome（最新版）
  ✅ Microsoft Edge（最新版）
  ✅ Safari（最新版 ※iOS対応に伴い）
  ❌ Internet Explorer（対象外・2022年サポート終了済み）
  ❌ Firefox（今回は対象外）

【利用環境の前提】
  - 社内端末はWindows PCに統一（会社支給）
  - 外出先はiPhone（会社支給）を使用
  - 個人端末（BYOD）の利用は想定しない
  - 社内ネットワーク（VPN）経由でのアクセスを前提とする

■ 前提条件
  - 上記ブラウザの最新版を動作確認対象とする
  - IE非対応は顧客と合意済み（Out of Scope）
  - 上記以外のデバイス・ブラウザへの対応は追加見積もりが必要
```

「IEは対象外」のように、**対応しないものも明記する**ことが重要です。
後から「IEでも動くようにしてほしい」と言われたときの根拠になります。

## まとめとネクストアクション

### 3つの重要ポイント

1. **対応デバイスが増えるほど、設計・実装・テストのコストが増える**
   PCのみとスマホ追加では工数が大きく変わる。
   IEへの対応は特にコスト増が大きく、超概算時点で要否を確認する。

2. **「誰が・どこで・何を使うか」から利用環境を逆算する**
   「デバイスは何ですか？」と直接聞かず、利用シーンを聞くことで
   顧客が気づいていない必要デバイスを引き出せる。

3. **対応しないデバイス・ブラウザも書面に残す**
   「IEは対象外」「タブレットは今回対象外」という合意を書面に残すことで、
   後からの追加要求に根拠を持って対応できる。
