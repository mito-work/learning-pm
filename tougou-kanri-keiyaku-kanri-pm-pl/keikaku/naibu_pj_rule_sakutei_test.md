# 【内部】プロジェクト（PJ）ルール策定

## 確認テスト

**Q1. プロジェクトルールを作る「本当の目的」として、最も適切なものはどれですか？**

A) メンバーが勝手な行動をしないように、厳しく監視・管理するため。

B) メンバーの個性を消して、全員がロボットのように同じ作業をするため。

C) トラブルが起きた際の「判断基準」を仕組み化し、炎上を防ぐため。

**Q2. 小規模なプロジェクト（3〜5名）において、ルール作りで注意すべき点は何ですか？**

A) 小規模こそ「なあなあ」になりやすいため、簡潔で明確なルールを必ず作る。

B) 人数が少なく全員の顔が見えるので、特にルールを作る必要はない。

C) 大規模プロジェクトと同じ、数百項目の細かいルールをすべて適用する。

**Q3. 顧客から「ついでにこの機能も修正して」と口頭で頼まれました。ルール上、正しい対応はどれですか？**

A) 良好な関係を保つため、その場で快諾してすぐに作業に取り掛かる。

B) 「口頭での合意は禁止」というルールに従い、内容を記録してPM（責任者）に報告する。

C) 自分の判断で「これくらいなら大丈夫」と判断し、内緒で対応する。

---

## 👉 **正解を確認する Q1: [ C ] / Q2: [ A ] / Q3: [ B ]**

### 【解説】

#### Q1：判断を「仕組み」に変える

正解は **C** です。
ルールは監視（A）のためではなく、迷った時の「ガイドライン」です。判断を仕組みにすることで、誰が担当しても同じ正しい判断ができるようになり、チーム全体の安全性が高まります。

* **ポイント：** ルールは「平常時」ではなく「揉めた時」に真価を発揮します。

#### Q2：小規模ほど「属人化」が怖い

正解は **A** です。
「人数が少ないから大丈夫（B）」という油断が、実は一番危険です。兼務が多く記録が雑になりがちな小規模PJこそ、エッセンスを絞った簡潔なルールが絶大な効果を発揮します。

* **ポイント：** 「3点ルール（スコープ・記録・報告）」だけでも設定しましょう。

#### Q3：無償対応の増殖を防ぐ

正解は **B** です。
口頭での「いいですよ」は、後にスコープ逸脱や工数超過（CやAの結果）を招く最大の原因です。必ず「記録」を残し、責任者が「コストやスケジュールへの影響」を判断するルートを通す必要があります。

* **ポイント：** 「優しさ」で引き受けたことが、チームを赤字にする原因になります。
