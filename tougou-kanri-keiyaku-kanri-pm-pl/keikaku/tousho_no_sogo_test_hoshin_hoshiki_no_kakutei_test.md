# 当初の総合テスト方針／方式の確定

## 確認テスト

**Q1. 総合テストで重点的に確認すべき内容として、最も適切なものはどれですか？**

A) プログラム内のIF文やループ処理が正しく記述されているか。

B) 画面のボタンを押したときに、隣のシステムへデータが届くか。

C) 実際の業務の流れ（シナリオ）に沿って、最後まで問題なく操作できるか。

**Q2. 総合テストの「完了基準」を最初に決める最大のメリットは何ですか？**

A) テスト担当者が、毎日何時に帰れるかを計算しやすくするため。

B) お客さまと「どこまで直せば合格か」の合意ができ、検収トラブルを防げるため。

C) プログラムのバグを1つ残らず、完全に消し去ることができるため。

**Q3. 小規模プロジェクトにおいて、効率的に総合テストを進める「方式」の例はどれですか？**

A) すべてのプログラムコードを一行ずつ再確認する。

B) 実際の仕事の流れを再現した「業務シナリオ」をベースにテストする。

C) 外部のテスト専門会社に、全ての判断を丸投げする。

---

## 👉 **正解を確認する Q1: [ C ] / Q2: [ B ] / Q3: [ B ]**

### 【解説】

#### Q1：業務妥当性の確認

正解は **C** です。
Aは「単体テスト」、Bは「結合テスト」の主な目的です。総合テストは、システムが「ユーザーの仕事に役立つ完成品になっているか」という**業務観点**が主役です。

* **ポイント：** 「システムが動く」のその先、「業務が回る」を確認します。

#### Q2：トラブルの回避

正解は **B** です。
バグを完全にゼロにすることは現実的に難しいため、「重大な不具合はゼロ、軽微なものは後日修正」といった**終わりのルール**を決めます。これが無いと、いつまでも検収（お支払い）がされません。

* **ポイント：** 総合テストは「品質の着地点」を決める契約的な側面を持ちます。

#### Q3：シナリオベーステスト

正解は **B** です。
限られた時間の中で最大の安心を得るには、細かい部品を見るよりも「一番よく使う業務の流れ」を優先してテストするのが最も効率的です。

* **ポイント：** 「よくある1日」を再現するテストが、最もバグを見つけやすく、安心感を与えます。
