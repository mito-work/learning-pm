# 当初の詳細設計／実装／単体テスト方針／方式の確定

## 確認テスト

**Q1. この工程における「本質」として最も適切なものはどれですか？**

A) 1分でも早くキーボードを叩き、コードの量を増やすこと。

B) 画面の見た目をユーザーの好みに合わせて何度も修正すること。

C) 設計思想をコードとして具体化し、単体レベルで品質を保証すること。

**Q2. 「方式（進め方）」に該当するものは次のうちどれですか？**

A) プログラムの実行速度をコンマ1秒まで追求する。

B) プルリクエスト（PR）ベースで、必ず第三者のレビューを経てから反映させる。

C) 単体テストの網羅率（カバレッジ）を100%に設定する。

**Q3. 方針を決めずに実装を進めた結果、起きやすい問題はどれですか？**

A) 結合テストの段階で、予期せぬ不具合が大量に発生し、工数が爆発する。

B) プログラミング言語の機能が制限され、開発ができなくなる。

C) パソコンの動作が重くなり、開発効率が下がる。

---

## 👉 **正解を確認する Q1: [ C ] / Q2: [ B ] / Q3: [ A ]**

### 【解説】

#### Q1：品質の具体化

正解は **C** です。
この工程は「ただ作る」のではなく、これまでの設計思想を「動く形」にし、品質を証明する重要なフェーズです。

* **ポイント：** コードを書くのは手段であり、目的は「品質の具体化」です。

#### Q2：進め方のルール

正解は **B** です。
Bは開発の「手順・進め方」を指します。AとCは「どのような品質にするか」という「方針（思想）」にあたります。

* **ポイント：** 良い手順（方式）が、良い品質（方針）を支えます。

#### Q3：後工程でのツケ

正解は **A** です。
単体レベルでの品質がバラバラだと、複数の部品を組み合わせる「結合テスト」で問題が噴出します。

* **ポイント：** 「後で直せばいい」は、結果的に一番コストが高くつきます。
