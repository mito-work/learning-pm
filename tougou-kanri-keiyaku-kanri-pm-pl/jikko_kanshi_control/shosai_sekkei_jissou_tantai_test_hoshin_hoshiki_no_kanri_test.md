# 詳細設計／実装／単体テスト方針／方式の管理

## 確認テスト

**Q1. 詳細設計の役割として、正しいものはどれですか？**

A) システム全体の予算や納期をお客さまと合意すること。

B) プログラミング（実装）ができるレベルまで、具体的に中身を指示すること。

C) すべての機能をつなげて、実際の業務が回るかを確認すること。

**Q2. 単体テストフェーズにおいて、PL（リーダー）が重点的に確認すべきことは何ですか？**

A) テストの観点に漏れがないか、異常な操作をした場合も考慮されているか。

B) メンバーが毎日何時に出勤し、何時に退勤しているか。

C) お客さまへの追加費用の請求書が作成されているか。

**Q3. 「レビューを省略する」ことで発生するリスクとして、最も当てはまるものはどれですか？**

A) 作業スピードが上がり、プロジェクトが予定より早く終わる。

B) 担当者ごとの勝手な解釈やミスが見逃され、後の工程で致命的なトラブルになる。

C) サーバーの電気代が安くなる。

---

## 👉 **正解を確認する Q1: [ B ] / Q2: [ A ] / Q3: [ B ]**

### 【解説】

#### Q1：詳細設計の定義

正解は **B** です。
Aは「契約・要件定義」、Cは「総合テスト」の役割です。詳細設計は、実装者が迷わずにコードを書けるようにするための**「詳細な設計図」**です。

* **ポイント：** 詳細設計が曖昧だと、実装でバグが量産されます。

#### Q2：PLの役割

正解は **A** です。
BやCはPMの管理領域（勤怠や契約）です。PLは技術の責任者として、**「テストの質（網羅性）」**に責任を持ちます。

* **ポイント：** 「正常系（うまくいく時）」だけのテストは、テストとは呼びません。

#### Q3：レビューの重要性

正解は **B** です。
短期的には早く終わったように見えますが、レビューで潰せなかったミスは「結合テスト」や「リリース後」に牙を剥きます。その時の修正コストは、レビューの数倍から数十倍に膨れ上がります。

* **ポイント：** レビューは「時間の無駄」ではなく「時間の貯金」です。
