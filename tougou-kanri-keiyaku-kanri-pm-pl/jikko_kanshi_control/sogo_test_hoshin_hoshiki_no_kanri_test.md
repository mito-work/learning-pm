# 総合テスト方針／方式の管理

## 確認テスト

**Q1. 総合テスト管理において、最も重視すべきことは何ですか？**

A) プログラムが1行も間違わずに書かれていることを確認すること。

B) 実際の業務の流れ（シナリオ）に沿って、システムが目的を果たせるか確認すること。

C) すべてのテストを、予定より1週間早く終わらせること。

**Q2. PL（リーダー）が総合テスト中に行う「技術的リスク評価」とは、具体的にどんなことですか？**

A) 「この不具合の直し方は、他の機能に悪影響を与えないか？」を分析すること。

B) お客さまとの打ち合わせ場所をどこにするか決めること。

C) メンバーの給料をいくらにするか計算すること。

**Q3. 総合テストを終了してもよいと判断できる基準として、適切なものはどれですか？**

A) 予定していたテスト期間がすべて終了した。

B) 致命的な不具合がゼロになり、あらかじめ決めた「完了定義」をすべて満たした。

C) 担当者が「もうバグは出ないと思います」と言った。

---

## 👉 **正解を確認する Q1: [ B ] / Q2: [ A ] / Q3: [ B ]**

### 【解説】

#### Q1：総合テストの目的

正解は **B** です。
個別の正しさよりも、**「全体として仕事が回るか」**が重要です。どれほどコードが綺麗でも、注文ボタンが機能しなければシステムとしては失格です。

* **ポイント：** 総合テストは「ユーザーの視点」で行う最後の砦です。

#### Q2：PLの役割

正解は **A** です。
BやCはPMや管理部門の仕事です。PLは技術のプロとして、**「修正による二次被害（デグレード）」**や「システムの安定性」を見極めます。

* **ポイント：** PLは「技術的な太鼓判」を押す係です。

#### Q3：終了判定

正解は **B** です。
期間が来たから（A）や、個人の勘（C）で終わらせるのはプロの管理ではありません。最初に決めた**「完了定義（ルール）」**という客観的な物差しで判断します。

* **ポイント：** 完了定義は、PMが自信を持って「リリースOK」とお客さまに伝えるための根拠になります。
