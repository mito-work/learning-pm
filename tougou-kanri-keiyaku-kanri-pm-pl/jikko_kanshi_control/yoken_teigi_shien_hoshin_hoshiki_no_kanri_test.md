# 要件定義支援方針／方式の管理

## 確認テスト

**Q1. 要件定義における「管理」の本当の目的は何ですか？**

A) お客さまの要望をすべて聞き入れ、満足度を最大化すること。

B) 最初に決めた「進め方」や「範囲」からズレないよう監視し、是正すること。

C) 議事録をきれいに清書して、フォルダに整理しておくこと。

**Q2. 「スコープ膨張」が起きているサインとして、正しいものはどれですか？**

A) 当初予定していた機能リストにはない項目が、議論の半分以上を占めている。

B) 打ち合わせの回数が予定通り週に1回行われている。

C) お客さまが「使いやすいシステムになりそうだ」と喜んでいる。

**Q3. 「要件凍結」を行った後に、どうしても変更したい要望が出た場合の正しい対応は？**

A) 凍結したのだから、どんな理由があっても一切受け付けない。

B) 現場判断ですぐに修正し、こっそりプログラムを書き換える。

C) 「変更管理台帳」に記録し、工数や納期への影響を分析して、承認を得る。

---

## 👉 **正解を確認する Q1: [ B ] / Q2: [ A ] / Q3: [ C ]**

### 【解説】

#### Q1：管理の目的

正解は **B** です。

Aは「要求収集」であり、管理ではありません。管理とは、プロジェクトが予算や納期の枠（ガバナンス）から飛び出さないようにコントロールすることです。

* **ポイント：** 「いいなり」になるのは管理ではありません。

#### Q2：スコープ膨張の検知

正解は **A** です。

「ついでに」「これも」という会話が増え、当初の計画にない作業が膨らんでいる状態は非常に危険です。

* **ポイント：** 「追加」を「追加」として認識できなくなった時、炎上が始まります。

#### Q3：変更管理プロセス

正解は **C** です。

変更を一切拒絶（A）するとビジネスが回りませんが、無償で受ける（B）とプロジェクトが破綻します。影響を可視化して「やる・やらない」を判断する土俵に乗せることがプロの対応です。

* **ポイント：** 変更は「悪」ではなく、「管理されるべき対象」です。
