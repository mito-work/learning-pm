# 契約内容（納品手続き、検収手続き、請求）のクロージング

## 確認テスト

**Q1. プロジェクトにおける「契約」の本来の役割として、最も適切なものはどれですか？**

A) 作業を開始するための単なる手続き

B) プロジェクトの「終わり方」を事前に設計すること

C) 相手に厳しい条件を押し付けるための手段

**Q2. 「検収（けんしゅう）」フェーズで行うべき正しい行動はどれですか？**

A) 成果物を提出して、すぐに請求書を送る

B) 成果物が契約通りの基準を満たしているか、相手に確認してもらう

C) 相手の反応を待たずに、次の新しいプロジェクトを開始する

**Q3. 納品トラブルを防ぐために、契約時に決めておくべき「納品の定義」に含まれないものはどれですか？**

A) どのような形式（PDF、紙、データ等）で渡すか

B) いつまでに渡すか

C) 相手がその成果物を使ってどれくらい儲けるか

---

## 👉 **正解を確認する Q1: [ B ] / Q2: [ B ] / Q3: [ C ]**

### 【解説】

#### Q1：終わりの設計図

正解は **B** です。
契約は単なる事務作業ではなく、トラブルを防ぐための「ゴールテープの設置」です。Aのように捉えると後で揉めますし、Cのように攻撃的な姿勢では信頼を失います。

* **ポイント：** 「どうなればこの仕事は終わりか？」を契約時に握ることがプロの鉄則です。

#### Q2：合否確認のプロセス

正解は **B** です。
「納品」は渡すこと、「検収」は合格をもらうことです。Aのように検収を飛ばすと、後で「不備があるからお金は払えない」と言われるリスクがあります。

* **ポイント：** 検収合格のメールや書面をもらうまでが、あなたの「責任範囲」です。

#### Q3：実務的な納品定義

正解は **C** です。
納品の定義で必要なのは「何を（形式）」「いつ（期限）」「どこに（場所）」です。Cの「相手が儲かるかどうか」は相手のビジネスの結果であり、あなたの納品手続きそのものの定義には含まれません。

* **ポイント：** 「納品物のリスト」を契約書に明記するだけで、再提出のリスクは激減します。
