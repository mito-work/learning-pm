# ステークホルダー管理 > 計画

## 【対客】内部決済者／上長を巻き込んだ決済者とのホットライン確立

---

## 導入

### このスキルを身につけると、何が変わるか

「顧客の役員が出てくるような大きな問題が起きたとき、PMだけでは太刀打ちできなかった」
「顧客との関係が悪化し始めていたが、PMレベルでは修復が難しかった」
「顧客の決済者と自社の間に接点がなく、いざというとき誰も動けなかった」——

プロジェクトで本当に重大な問題が起きるとき、PMと顧客担当者の間だけでは解決できないことがあります。
スコープの大幅変更、費用の追加、関係の悪化——これらは「経営レベルの判断・関係」が必要です。
このスキルは、**計画フェーズのうちに自社の上長と顧客の決済者の間に「上層同士のホットライン」を設計し、いざというときに機能する関係を作っておく**技術です。

このスキルを学ぶことで：
- 重大課題・交渉事が発生したとき、PMだけで抱えずに上層を動かせる
- 顧客の決済者に対して、PMを超えたレベルの関係性が生まれる
- 「いざというときのルート」が計画段階から確保される
- 顧客との関係が「担当者レベル」だけに依存するリスクを減らせる

---

## 学習目標

このテキストを読み終えると、以下ができるようになります。

1. **「PMレベルのライン」と「上層ライン」の2段構えの意義を説明できる**
2. **内部上長を巻き込んで顧客決済者との接点を作る具体的なタイミングと方法を実践できる**
3. **上層ホットラインを「日常」ではなく「いざというとき」に正しく機能させる設計ができる**

## 本編

---

### Section 1：なぜ「上層同士のホットライン」が必要か

**一言でいうと：PMレベルで解決できる問題には限界がある。上が動けるルートを先に作っておく。**

プロジェクトのコミュニケーションには、構造的に「レベル」があります。

```
【一般的なプロジェクトのコミュニケーション構造】

  顧客側                       ベンダー側
  ──────────────────────────────────────
  役員・経営層         ←─？─→  役員・上長
                                  （ここに接点がないことが多い）
  ──────────────────────────────────────
  部長・プロジェクトオーナー ←─？─→  部長・PM上長
                                  （形式的な関係のみのことが多い）
  ──────────────────────────────────────
  顧客側PM・担当者      ←───→  PM・PL
                                  （ここだけ機能している）
```

多くのプロジェクトでは、PMと顧客担当者の間だけが実質的に機能しており、上層の接点は名刺交換程度で終わっています。

**このとき起きる問題：**
```
重大な問題が発生
  → PMが顧客担当者に報告
  → 顧客担当者が上司に報告
  → 顧客役員が「そんな話は聞いていない」「誰がベンダーの責任者なのか」と言い出す
  → PMが1人で顧客役員と対峙することになる
  → 自社上長を呼ぶ余裕も段取りもない
```

逆に上層同士の接点があれば：
```
重大な問題が発生
  → PMが顧客担当者に報告（通常ルート）
  → 自社上長が顧客決済者に直接連絡（上層ライン）
  → 「弊社としても最重要事項として対応します」というメッセージを伝える
  → PMは現場対応に集中でき、上層が関係を安定させてくれる
```

### Section 2：「2段構え」の設計——日常ラインと上層ライン

**一言でいうと：日常はPMが動く。上層ラインは「いざというとき専用」。使い分けを最初に決める。**

上層同士のホットラインを「常時使う」ことには弊害があります。

```
上層ラインを常時使うと起きる問題：
  ・顧客の担当者が「なぜ自分を飛ばして役員に連絡するのか」と不満を持つ
  ・担当者との信頼関係が崩れる
  ・上長が細かい日常的な話に巻き込まれ、本当に重要な場面で機能しにくくなる
```

上層ラインは「有事専用・特別な場面専用」として設計します。

#### 2段構えの役割分担

| 場面 | 使うライン | 具体例 |
|-----|---------|------|
| **日常的な進捗・課題** | PMライン | 週次定例・課題管理表の更新・仕様確認 |
| **スコープ変更の交渉** | PMライン（一次）→ 上層ライン（合意形成） | 追加費用の提示・変更内容の合意 |
| **重大な品質問題・障害** | PMライン（初動）＋ 上層ライン（関係維持） | 障害発生時の謝罪・対応方針の共有 |
| **関係の悪化・信頼の危機** | 上層ライン（主導） | 顧客からのクレーム・不信感の表明 |
| **契約変更・大幅な条件変更** | 上層ライン（主導） | 再見積もり・期間延長・体制変更 |

「上層ラインは年に数回しか使わないかもしれない。でも使えないと取り返しがつかない。」
この感覚が、計画フェーズで上層ホットラインを準備する動機です。

---

### Section 3：内部上長を巻き込む——タイミングと方法

**一言でいうと：「この場で引き合わせる」という設計を、計画フェーズで決めておく。**

内部上長と顧客決済者の接点を作るタイミングは、自然に生まれる「節目」を活用します。

#### 接点を作る主要なタイミング

```
① キックオフミーティング
  → 「弊社からは担当PM○○に加え、
     本プロジェクトを支援する上長の○○も同席します」と設定
  → 名刺交換・顔合わせが自然にできる

② 月次定例会（重要な節目のタイミング）
  → 「フェーズ区切りのため、今回は弊社上長の○○も同席させてください」
  → 要件定義完了・基本設計完了などの節目に設定

③ 提案プレゼン・見積もり提示の場
  → 「正式な提案のため、弊社責任者の○○がご説明します」
  → 顧客の決済者が出席する場に合わせて自社上長を連れていく

④ 問題・課題の報告（重大なもの）
  → 「重要なご報告のため、弊社PMに加え上長の○○も同席させてください」
```

**最も自然な接点は「キックオフ」**です。
プロジェクト開始のキックオフに上長を連れていくことで、「初顔合わせ」を形式的でなく自然に行えます。
ここで「何かあれば直接ご連絡ください」という言葉と名刺を渡すことが、ホットラインの種まきになります。

---

### Section 4：上長を「巻き込む」ための社内調整

**一言でいうと：上長に「なぜ自分が出る必要があるか」を納得してもらうことが先決。**

上層ホットラインを確立するには、自社上長の協力が必要です。
前の教材（内部ホットライン確立）で学んだ「上長との関係」が土台になります。

#### 上長への説明の構成

```
① 顧客の決済者は誰か（顧客組織の上長の役職・背景）
② なぜ接点を作っておく必要があるか（プロジェクトのリスク・重要性）
③ いつ・どの場で引き合わせたいか（具体的なタイミング）
④ 上長に求めること（挨拶だけか・定期的な関与か）
```

#### 上長への説明の例文

```
「本プロジェクトは○億円規模で、顧客側の最終決裁者は
 取締役の○○様です。

 キックオフの際に、上長にも同席いただき、
 ○○取締役とご挨拶いただけますか？

 普段のやり取りはPMである私が行いますが、
 スコープ変更や重大な課題が発生した際に、
 上層同士の直接のやり取りができる状態を
 作っておきたいと考えています。

 キックオフ（○月○日）の30分のみのご参加で大丈夫です。」
```

**「何をしてほしいか」を具体的に（時間・場・役割）明示することが上長の承諾を得やすくする。**

---

### Section 5：ホットラインを「機能させる」ための維持管理

**一言でいうと：作っただけで終わらせない。薄く・継続的に接点を維持する設計をする。**

キックオフで引き合わせたとしても、その後まったく接触がなければ「ホットライン」とは呼べません。
上層ラインを「いざというとき機能する」状態に保つには、定期的な「薄い接触」が必要です。

#### 上層ラインの維持方法

```
薄く継続する接触の例：
  ・月次報告メールの宛先に顧客決済者を追加する（CC程度でOK）
  ・重要なマイルストーン達成時に上長から顧客決済者へ一言メールを送る
    「先月の要件定義完了について、ご協力に感謝申し上げます」
  ・フェーズ節目の定例会に上長が同席するタイミングを定期的に設ける（四半期に1回程度）
```

これらは「頻繁すぎず・途絶えすぎず」がポイントです。
四半期に1度、上長が顧客決済者に一言送るだけで「接点は生きている」という状態が維持できます。

#### PMの役割：上層ラインを「支える」

上層ラインの維持で、PMがやるべきことがあります。

```
PMがやること：
  ・上長が顧客決済者に送るメールの下書きを作る
  　（上長は内容を知らないため、PMが情報を提供する）
  ・上長が同席する前に「今の状況・顧客の関心事」を5分でブリーフする
  ・上長が顧客決済者に話した内容を確認し、認識のズレがないか確認する
```

上層ラインは「上長が自分でやるもの」ではなく、「PMが設計し・PMが支えるもの」です。

## まとめとネクストアクション

### 3つの重要ポイント

1. **PMレベルと上層レベルの「2段構え」を計画段階から設計する**
   日常はPMが動く。スコープ変更・重大障害・関係悪化には上層ラインを使う。
   「いざというときに上が動けるかどうか」が、大きな問題での結末を左右する。

2. **接点のタイミングはキックオフが最適。上長と顧客決済者を自然に引き合わせる**
   「プロジェクト開始の挨拶」という文脈が最も自然な接点の作り方。
   上長への社内調整では「何をしてほしいか・時間・場・役割」を明確にする。

3. **作ったホットラインは「薄く・継続的に」維持する。PMが支える設計にする**
   四半期に1度の一言メール・フェーズ節目の同席——途絶えない接点が「いざというとき機能するライン」を維持する。
   上長が動くための情報・下書きを提供するのもPMの仕事。
