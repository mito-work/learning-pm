# ステークホルダー管理 > 計画

## 【内部】決済者／上長とのホットライン確立／リレーション確立

---

## 導入

### このスキルを身につけると、何が変わるか

「上長に相談したいのに、普段から接点がなくて話しかけにくい」
「問題が大きくなってから初めて上長に報告して、なぜ早く言わなかったのかと叱られた」
「エスカレーションしたのに上長が状況を理解しておらず、意思決定が遅れた」——

プロジェクトの計画フェーズで上長との関係を作っておくことは、後の「相談・報告・エスカレーション」を支える土台です。
問題が起きてから関係を作ろうとしても、すでに手遅れです。
このスキルは、**プロジェクト計画の段階で、意図的に「ホットライン（緊急時でも即座に話せる通信路）」と「リレーション（日常的な信頼関係）」を確立する**技術です。

このスキルを学ぶことで：
- 問題が起きたとき、上長に迷わず相談・エスカレーションできる
- 上長の判断基準・関心事を理解し、的確な報告ができる
- 「助けてもらいやすい関係」を先に作っておける
- 上長が「このPMは信頼できる」と感じる情報共有ができる

---

## 学習目標

このテキストを読み終えると、以下ができるようになります。

1. **「ホットライン」と「リレーション」の違いと、それぞれを確立するための具体的なアクションを説明できる**
2. **上長の判断基準・関心事を把握し、報告の内容と頻度を設計できる**
3. **「良い報告だけ」ではなく「悪い情報ほど早く伝える」習慣をつくれる**

## 本編

---

### Section 1：「ホットライン」と「リレーション」の違い

**一言でいうと：ホットラインは「いざというとき話せる道」、リレーションは「その道を日頃から整備すること」。**

2つの概念を整理します。

| 概念 | 意味 | 確立できていない状態 |
|-----|-----|----------------|
| **ホットライン** | 緊急時・重要な判断が必要なとき、上長に即座に連絡・相談できる「通信路」が確保されている状態 | 「急いで相談したいのに、上長がつかまらない」「相談していい場かどうかわからない」 |
| **リレーション** | 上長との日常的な信頼関係。「このPMなら任せられる」という安心感が積み上がっている状態 | 「普段接点がないから、問題が起きても相談しにくい」「上長がプロジェクトの状況を把握していない」 |

**メタファー：**
ホットラインは「消防署への直通電話」です。
いざというとき確実につながる専用線。
でも、火事が起きてから初めてその番号を調べても遅い。
リレーションは「日頃から消防署の人たちと顔見知りになっておくこと」です。
顔見知りなら電話一本で状況を伝えやすく、適切な支援が速く得られます。

**重要：計画フェーズで確立しておく理由**
問題が大きくなってから関係を作ろうとしても、上長は「なぜ今まで連絡がなかったのか」という気持ちになります。
プロジェクトが順調なうちに関係を作っておくことで、問題が起きたときの相談・支援が自然に流れます。

---

### Section 2：ホットラインを確立する——「報告の設計」

**一言でいうと：「何を・いつ・どの形で報告するか」を計画の段階で上長と合意する。**

ホットラインの確立は「連絡先を知っている」だけでは不十分です。
「どんな情報をどのタイミングで共有するか」を事前に設計し、上長と合意しておくことが重要です。

#### ① 定期報告の設計

```
上長への定期報告で合意すべきこと：

・頻度：週次？月次？マイルストーン単位？
・形式：口頭（打ち合わせ）？メール？資料送付？
・内容：進捗・課題・リスクのどこまでを共有するか
・所要時間：15分程度か、30分の打ち合わせか
```

プロジェクト開始時に「○○さんには週次でメールで進捗を送ります。
月次で15分の確認時間をいただけますか？」と合意しておきます。
上長から「そんな頻度では多すぎる」「もっと詳しく知りたい」という調整が入ることもあります。
調整ができることが重要です。

#### ② 緊急時の連絡ルートを事前確認する

```
計画フェーズで確認しておくこと：

「緊急の課題が発生した場合、メールと電話どちらが良いですか？
 夜間・休日の連絡が必要な可能性がある場合は、
 どのような状況であれば連絡してよいですか？」
```

「緊急時にどう連絡するか」を事前に決めておくことで、
いざというとき「連絡してよかったのか」という迷いが消えます。

#### ③ エスカレーションの判断基準を合意する

```
上長に確認すること：
「どのような状況になったら、上長にエスカレーションすべきですか？
 ・コスト超過：予算の何%超えたら報告？
 ・スケジュール遅延：何日遅れたら報告？
 ・課題のレベル：どの優先度から上長に報告？」
```

この確認をしておくと、PMは「これは報告すべきか」という迷いが減ります。
上長も「なぜ報告しなかったのか」という不満が減ります。

---

### Section 3：リレーションを確立する——「信頼の積み上げ」

**一言でいうと：信頼は「大きな報告」ではなく「小さな積み重ね」で作られる。**

リレーションの確立は、特別なことをする必要はありません。
日常的な小さな接点を意識的に増やすことで、自然に信頼関係が育ちます。

#### ① 小さな「情報共有」から始める

プロジェクト開始時、上長にとって「プロジェクトの現状を把握する機会」は限られています。
PMから積極的に情報を届けることで、上長は「このPMはちゃんと情報を共有してくれる」という安心感を持ちます。

```
小さな情報共有の例：
・「先週、顧客と初回打ち合わせを行いました。顧客の期待値は○○で、
   主な課題になりそうなのは○○です。」（メール1通）
・「体制図が確定しましたので、共有します。」（添付1つ）
・「一点気になることがあるのでご意見をください。（3分で済みます）」（声がけ）
```

「良いことだけ」を報告するのではなく、「気になっていること」も早めに共有することが重要です。

#### ② 上長の「判断基準・関心事」を把握する

上長によって、プロジェクトに対して気にすることが違います。

```
上長の関心事の例：
・コスト重視型：「予算内に収まるか」が最優先
・リスク重視型：「顧客との関係で問題が起きないか」を気にする
・スピード重視型：「スケジュール通りに進んでいるか」を重視
・品質重視型：「顧客に出すものの品質が落ちていないか」を確認したい
```

上長の関心事を把握することで、報告の「切り口」が変わります。
「コスト重視型の上長」には進捗だけでなくコスト状況を合わせて報告する、という具合です。
「この人に話すときは○○を最初に伝える」という判断ができるようになります。

#### ③ 「助けを求める」ことをためらわない

「上長に相談すると弱く見られる」という思い込みがあるPMは多いです。
しかし、適切なタイミングで相談できるPMは、上長から見ると「信頼できるPM」です。

```
良い相談の例：
「○○という課題が出てきました。私は△△の対応を考えていますが、
 上長の経験からアドバイスをいただけますか？」

→ 「自分で考えた上で相談している」という姿勢が伝わる
→ 上長は「このPMは自走できる、かつ適切に支援を求められる」と感じる
```

「自分では解決できない」ではなく「より良い判断のために意見を聞きたい」というスタンスで相談することが重要です。

---

### Section 4：「悪い情報ほど早く伝える」習慣

**一言でいうと：良い報告は誰でもできる。上長が信頼するのは「悪い情報を隠さないPM」。**

リレーション構築において最も重要な習慣は、**悪い情報・問題の兆候を早めに報告する**ことです。

#### なぜ「悪い情報の早期共有」が信頼を生むのか

```
悪い情報を隠した場合：
  問題が小さい → PMが1人で抱える → 問題が大きくなる → 上長に発覚
  → 「なぜ早く言わなかったのか」という不信感

悪い情報を早期共有した場合：
  問題が小さい → PMが早期に上長へ報告 → 上長が支援・方針判断できる
  → 「このPMは隠さない・信頼できる」という安心感
```

プロジェクトに問題は必ず起きます。
「問題がない」という報告を続けていたPMが突然「実は…」と言い出すより、
「小さな問題が出ました」を早めに言い続けるPMの方が、圧倒的に信頼されます。

#### 早期報告の「伝え方」

悪い情報を伝えるとき、「謝罪」より「現状と対応策」をセットで伝えます。

```
良い伝え方：
「○○という問題が発生しました。
 現在の状況は○○で、私は△△の対応を進めています。
 ○○のリスクが残っていますが、□□で対処する予定です。
 ご意見・ご判断をいただきたい点は○○です。」

→ 問題を認識している・対応を考えている・判断を仰いでいる
```

「問題が起きました。どうしましょう？」だけでは、上長に丸投げしているように見えます。
「状況・自分の対応案・上長に判断してほしいこと」の3点を揃えることが重要です。

### Section 5：「ホットライン・リレーション管理表」で状態を可視化する

**一言でいうと：関係の「現在地」を記録して、定期的に見直す。**

「リレーション確立」は感覚的になりがちです。
以下のような管理表を作ることで、関係構築の状態を可視化します。

#### ホットライン・リレーション管理表

| 上長名 | 役割 | 定期報告頻度 | 緊急連絡先確認 | エスカレ基準合意 | 関心事 | 最終接触日 |
|------|-----|-----------|------------|-------------|------|---------|
| 山田部長 | 最終承認者 | 月次（確認済） | ✅ 携帯あり | ✅ 予算10%超・納期2週遅延 | コスト・顧客関係 | 2026/06/15 |
| 鈴木課長 | 日次の上長 | 週次（確認済） | ✅ チャット即応 | ✅ High課題以上 | スケジュール・品質 | 2026/06/20 |
| 佐藤部長（上位） | 重大事象のエスカレ先 | 月次報告のみ | ❌ 未確認 | ❌ 未合意 | 未確認 | — |

「❌」の欄がアクションポイントになります。
特に「緊急連絡先の未確認」「エスカレーション基準の未合意」は、プロジェクト計画フェーズ中に解消しておくべき項目です。

## まとめとネクストアクション

### 3つの重要ポイント

1. **ホットラインは「いざというときに使う」ではなく「計画フェーズで設計する」もの**
   定期報告の頻度・形式、緊急時の連絡手段、エスカレーション基準を上長と事前合意する。
   合意がないまま進めると、「なぜ報告しなかったのか」という不満が必ず起きる。

2. **リレーションは「大きな出来事」ではなく「小さな積み重ね」で作られる**
   小さな情報共有・気になることの早期相談・悪い情報の隠さない報告——
   この日常の積み重ねが「このPMなら任せられる」という上長の安心感になる。

3. **「悪い情報ほど早く・対応案と一緒に」報告することが信頼の最大の証明**
   「状況・自分の対応案・上長に判断してほしいこと」の3点セットで伝える習慣が、
   上長との信頼関係を急速に深める。
