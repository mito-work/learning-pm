# ステークホルダー管理 > 立ち上げ

## 超概算：【対客】担当者に仮体制図のキーパーソンを埋める確認

---

## 導入

### このスキルを身につけると、何が変わるか

「誰に予算の話をすればいいかわからないまま、提案が進んでしまった」
「担当者しかつながっていなくて、意思決定が止まるたびに何週間も待たされた」
「後になって『実は決裁権を持っているのは別の部門長だった』と発覚した」——

超概算フェーズで必要なのは、顧客の「キーパーソン」が誰かを早期に把握することです。
このスキルは、**役割のみで作成した仮体制図を担当者に見せながら、各ポジションに入る人物を自然に確認していく**技術です。

このスキルを学ぶことで：
- 誰に予算の打診をすべきか、事前に把握できる
- 意思決定者と直接つながるための足がかりを作れる
- 「担当者を飛ばした」と感じさせずに、上層へのアプローチが設計できる
- キーパーソン情報が抜けたまま見積もりを進めるリスクを防げる

---

## 学習目標

このテキストを読み終えると、以下ができるようになります。

1. **仮体制図を「見せる道具」として使い、担当者に自然にキーパーソンを話してもらう問いかけができる**
2. **担当者が全員のキーパーソンを把握していない場合の対処ができる**
3. **確認した情報をもとに「次のアクション（引き合わせ依頼）」につなげられる**

---

## 本編

---

### Section 1：なぜキーパーソンを「仮体制図を通じて」確認するのか

**一言でいうと：「決裁者は誰ですか」と直接聞くと警戒される。体制図を見せながら聞けば、情報が自然に出てくる。**

多くのPMが経験する失敗がこれです。

```
【よくある失敗】
  PM：「ところで、最終的な予算の決裁者はどなたになりますか？」
  担当者：「……それは上の者に確認してから改めて連絡します」
  → 数週間、返事が来ない
```

「誰が決裁者か」を直接聞くことは、担当者に「自分を飛ばして上に行こうとしている」という警戒感を生みやすいです。

一方、前のステップで作成した「役割のみの仮体制図」を道具として使うと：

```
【仮体制図を使った確認】
  PM：「整理のため仮の体制図を作りました（体制図を見せる）。
       ここのプロジェクトオーナーのポジションには、
       貴社でいうとどなたが当てはまりますか？」
  担当者：「あ、それは○○部長ですね」
  → 自然な会話の流れで情報が引き出せる
```

「体制図を埋める作業をお願いしている」という文脈に置くと、担当者は「情報を取られている」ではなく「一緒に整理している」と感じます。
これが警戒感を下げる鍵です。

---

### Section 2：確認するキーパーソンの種類と優先順位

**一言でいうと：超概算フェーズでは「全員を把握する」より「予算と意思決定に関わる人を先に把握する」。**

仮体制図に埋めるキーパーソンには、確認の優先順位があります。

| 優先度 | 役割 | 確認理由 |
|------|-----|--------|
| ★★★ | **プロジェクトオーナー（予算決裁者）** | 予算打診の相手を特定するため |
| ★★★ | **プロジェクトの主担当者（窓口）** | 日常連絡の相手を確定するため |
| ★★ | **関係部門の責任者** | スコープに影響する意思決定者を把握するため |
| ★ | **エンドユーザー代表** | 要件確認の相手を把握するため |

超概算フェーズでは「★★★」だけでも把握できれば十分です。
「全員埋めなければいけない」と思う必要はありません。
空欄があっても「まだ未確定」という情報自体が価値を持ちます。

---

### Section 3：確認の進め方——問いかけの順序と言葉

**一言でいうと：上から順番に確認すると担当者が圧力を感じる。「一緒に埋める」作業感を演出する。**

体制図を使った確認には、話しかけ方の順序があります。

#### ステップ1：体制図を「整理中の素材」として渡す

```
「プロジェクトの全体像を整理するために
 ざっくりした体制のイメージを作ってみました。
 まだ役割しか入っていない仮のものですが、
 実際のお名前を教えていただけますか？」
```

「まだ仮のもの」という言葉が重要です。
完成形を押しつけているのではなく、「一緒に作っている」という印象を与えます。

#### ステップ2：担当者自身から確認する

```
「まず、今ご担当いただいている○○さんはこの
 プロジェクトマネージャーのポジションと理解していますが、
 合っていますか？」
```

担当者本人の役割から確認することで、体制図が「正しい」と感じてもらいやすくなります。
「この人はここ」が合っていると確認されると、続きを話してもらいやすくなります。

#### ステップ3：周辺のポジションを聞いていく

```
「このプロジェクトオーナー（スポンサー）のポジションには、
 貴社でいうとどなたが当てはまりますか？」

「このシステム担当のポジションには
 どなたがいらっしゃいますか？」
```

上位ポジション（プロジェクトオーナー）を聞くときは、
「予算を聞きたい」というニュアンスを出さず、「体制を整理したい」という文脈を保つことが大切です。

#### ステップ4：わからない場合への対処

```
「このポジションはまだ未定でしょうか？
 もしわかる範囲で教えていただければ
 後で確認していただくことでも大丈夫です」
```

担当者がわからないことを責めない・急かさないことが重要です。
「未定」「確認中」という情報も記録しておきます。

---

### Section 4：担当者が「教えにくい」情報への対処

**一言でいうと：「教えてくれない」場合は、情報を引き出す前に「理由の説明」が必要なことが多い。**

キーパーソンの確認で、担当者が教えにくいケースがあります。

#### ケース1：「上長には私から連絡します」と言われる

これは「私を通してください」というメッセージです。
この場合、まず担当者を通じたアプローチを続けます。

```
「もちろんです。体制図に名前だけ入れさせていただければ、
 ご連絡はすべて○○さんを通じて進めます。
 別途ご挨拶のお時間をいただけると助かりますが、
 それは後でご相談できますか？」
```

「名前だけ確認する → 連絡先は担当者経由でよい」と伝えると、教えてもらいやすくなります。

#### ケース2：「まだ決まっていない」と言われる

超概算フェーズでは実際に未定のことも多いです。
「未定」という状態自体を情報として記録します。

```
「わかりました。現時点では未定として記録しておきます。
 決まり次第教えていただけますか？
 このポジションが決まると、スケジュールの見通しが
 立てやすくなります。」
```

「決まると何がよくなるか」を添えることで、担当者が自発的に動きやすくなります。

#### ケース3：担当者自身が社内の構造を把握していない

大企業のプロジェクトでは、担当者が上層の構造を知らないことがあります。

```
「ご存じの範囲で結構です。
 わからない部分は空欄にしておきます。
 後で○○さんが確認いただける際に
 教えてもらえれば大丈夫です。」
```

「全部知っていて当然」という態度を取らないことが重要です。

---

### Section 5：確認した情報を「次のアクション」につなげる

**一言でいうと：キーパーソンの名前を聞いて終わりにしない。「その方にご挨拶したい」という次の一手を設計する。**

仮体制図にキーパーソンが入ったら、それをもとに次のアクションを設定します。

#### キーパーソンとの接点を作る依頼

```
「プロジェクトオーナーの○○部長には、
 今後の提案に向けて一度ご挨拶させていただけますか？
 30分程度で構いません。○○さんにご調整いただくことは
 可能でしょうか？」
```

「紹介してほしい」ではなく「ご挨拶させてほしい」という表現が自然です。
「30分程度」と具体的な時間を提示することで、担当者が上長にお願いしやすくなります。

#### 体制図を共有して「合意の証拠」にする

確認が終わった体制図は、担当者に共有します。

```
「本日ご確認いただいた内容を体制図に反映して
 お送りします。内容をご確認いただき、
 修正があれば教えていただけますか？」
```

体制図を共有することで「確認事項のログ」が残ります。
また、担当者が「間違いがあったら修正する」という関与を持つことで、情報の正確性が上がります。

## まとめとネクストアクション

### 3つの重要ポイント

1. **「決裁者は誰ですか」と直接聞かず、仮体制図を見せながら自然に確認する**
   「体制図を一緒に埋める作業」というフレームが、担当者の警戒感を下げる。
   直接的な質問は「自分を飛ばそうとしている」という印象を与え、情報が得にくくなる。

2. **超概算フェーズは「全員を把握する」より「予算・意思決定に関わる人を先に把握する」**
   プロジェクトオーナー（決裁者）と主担当者（窓口）の2つが最優先。
   空欄があっても「未定」という情報自体が価値を持つ。

3. **確認した情報を「挨拶の依頼」という次のアクションにつなげる**
   名前を聞いて終わりにしない。「一度ご挨拶させてほしい」という一言が、
   担当者だけとのつながりから上層へのアクセスに発展させる鍵になる。
