# ステークホルダー管理 > 立ち上げ

## 超概算：【対客】決済担当者に予算の打診

---

## 導入

### このスキルを身につけると、何が変わるか

「予算はいくらですか？と聞くのは失礼な気がして、聞けなかった」
「こちらで見積もりを出したら予算オーバーで、一から作り直しになった」
「担当者はOKと言っていたのに、上司に通したら白紙になった」——

多くのPMが超概算の場面でつまずく原因は、「予算を聞かないまま見積もりを出す」ことです。
顧客の予算を知らずに作った超概算は、予算オーバーになることが多く、修正に時間を取られます。
このスキルは、**顧客の予算を正しい順序で確認し、現場担当者・決済担当者に超概算を打診するまでの一連の流れ**を身につける技術です。

このスキルを学ぶことで：
- 「予算を聞く」ことへの心理的な壁がなくなる
- 顧客の予算ステータス（決まっているか・これからかを）見極められる
- 予算の範囲内で超概算を組み立てる手順が身につく
- 担当者と決済担当者の認識のズレを構造的に防げる

---

## 学習目標

このテキストを読み終えると、以下ができるようになります。

1. **決済担当者と現場担当者の役割の違いを説明し、適切にアプローチできる**
2. **なぜ予算を最初に確認しなければいけないかを説明し、顧客に自然に聞ける**
3. **3ステップの手順で予算を確認し、決済担当者に超概算を打診できる**

## 本編

---

### この教材を読む前に：「予算」と「超概算」は別の数字

この2つの用語の区別が、以降のすべての判断基準になります。

| 用語 | 誰の数字か | 意味 |
|-----|---------|-----|
| **予算** | 顧客側の数字 | このプロジェクトに使える・使う予定の金額 |
| **超概算** | PM（ベンダー）側の数字 | このプロジェクトにかかるコストの最初の荒い見積もり |

```
正しい順序：
  顧客の予算（上限）を先に確認する
  ↓
  その予算内に収まる超概算を組み立てる

間違った順序：
  超概算を先に出す
  ↓
  「予算オーバーでした」→ 作り直し
```

「予算→超概算」の順を守ることが、この教材全体のテーマです。

---

### Section 1：「決済担当者」とは誰か

**一言でいうと：予算はお金の判断ができる人に、確認する必要がある。**

プロジェクトの窓口になる「現場担当者」と、予算を承認する「決済担当者」は、多くの場合別の人です。

| 役割 | 誰か | 関心事 |
|-----|-----|-------|
| **現場担当者** | 担当者・課長クラス | 機能・使い勝手・スケジュール |
| **決済担当者** | 部長・役員・経営者 | 費用対効果・リスク・予算内に収まるか |

現場担当者だけと話していると、こんな失敗が起きます。

```
よくある失敗：
  ① 担当者に「だいたいXXXX万円でできそうです」と伝える
  ② 担当者は「わかりました」と返事する
  ③ 担当者が上司に報告したら「そんな予算はない」と却下される
  ④ 「あの担当者はOKと言っていたのに…」という状況になる
```

**決済担当者に直接確認することが、後からの「聞いていない」「予算がない」を防ぐ唯一の方法です。**

現場担当者には「予算規模についてご確認させていただきたいため、決済権をお持ちの方に同席していただけますか？」と一声かけましょう。
最初は断られることもありますが、理由を添えると通りやすくなります。

---

### Section 2：「予算を聞く」ことへの心理的な壁を乗り越える

**一言でいうと：予算を聞けないのは失礼だからではない。聞く理由が整理できていないからだ。**

多くのPMが予算を聞けない理由は「失礼かもしれない」という感情です。
しかし実際には、**予算を聞かない方が顧客にとっても不利益**になります。

```
予算を聞かずに超概算を出した場合：

  PM：「超概算として○○○○万円です」
  顧客：「うちの予算は○○○万円だったので無理です」
  PM：「そうでしたか…では作り直します」
  ↓
  ・双方の時間を無駄にする
  ・顧客は「この会社は私たちの状況を理解していない」と感じる
  ・信頼が下がる
```

**予算を聞くことは、顧客の状況に合わせた提案をするための必須情報収集です。**

#### 予算を聞くときの3つの切り口

「予算はいくらですか？」だけでは聞きにくい場面でも、以下の問いに変換すると答えてもらいやすくなります。

```
① 投資規模の確認
  「今回のシステム化に向けて、どのくらいの規模を
   ご想定されていますか？」

② 費用対効果の確認
  「このシステムを導入することで、どのような効果・
   リターンを期待されていますか？
   その効果に対して、どのくらいの投資がふさわしいと
   お考えですか？」

③ リスク・痛みの確認
  「現状のままでいると、どのようなリスクや
   コストが発生しますか？
   そのリスクを解消するために、どのくらいの
   コストが許容できますか？」
```

「予算の背景にある理由」がわかれば、予算は自然に引き出せます。
顧客が「なぜそのコストをかけたいのか」を自分の言葉で語ったとき、予算は情報として出てきます。

#### 予算の聞き方：幅ではなく「上限」を聞く

話を引き出せたあと、具体的な金額を確認するときは**上限金額を聞く**のがポイントです。

```
幅で聞くと：
  PM：「3,000万円〜5,000万円くらいですか？」
  顧客：「そうですね、3,000万円で…」
       ↑ 下限で通されることが多い

上限で聞くと：
  PM：「上限はどのくらいまでご想定ですか？」
  顧客：「5,000万円までなら…」
       ↑ 超概算を組み立てる余地が大きくなる
```

幅（レンジ）で確認することは基本的に避ける。
ただし例外として、こちらから規模感を幅で出すことで顧客が初めて予算を教えてくれるケースもある。レアケースとして頭に入れておく程度でよい。

---

### Section 3：顧客の「予算ステータス」を見極める

**一言でいうと：「予算が決まっている」と「まだ決まっていない」は、対応が全く違う。最初にどちらかを確認する。**

超概算の打診に入る前に、顧客の予算がどの段階にあるかを確認します。

| ステータス | 意味 | 対応方針 |
|---------|-----|---------|
| **予算配分済み** | 承認された予算がすでに配分されている | その予算に収まる超概算を作る。上振れは絶対NG |
| **来期予算を申請中** | まだ予算承認前で、これから申請する | 超概算を根拠に予算申請を支援するイメージで進める |
| **検討段階・未定** | どのくらいかかるか知りたい段階 | 規模感を示しながら、予算確保に向けた動きを促す |

> ⚠️ 上記の確認で「予算を教えてもらえない」「決済担当者に接続できない」といった
> 障壁が生じた場合は、「超概算：【対客】担当者予算打診不可時の決済者確認」で
> 対処方法を確認してください。

#### 予算ステータスの確認方法

```
「この案件はすでに予算のご用意がある状態でしょうか？
 それとも、今回のお話を踏まえてこれから予算を
 確保していく段階でしょうか？」
```

この一問で、どちらのステータスかがほぼわかります。

#### 「予算配分済み」の場合の重要ルール

**超概算は予算を上回ってはいけません。**

```
正しい考え方：予算 → 超概算（の順）

  顧客の予算が5,000万円と決まっている
  ↓
  超概算は5,000万円の範囲内で組み立てる
  ↓
  「5,000万円で何ができるか」を提示するのがPMの仕事

間違った考え方：超概算 → 予算確認（の順）

  ・「とりあえず見積もって、後で調整する」
  ・予算を聞かずに出した概算が予算を超えていた
  ・「削ってほしい」という交渉になる
  → 顧客との関係が交渉・削減モードになる
```

### Section 4：3ステップで予算を確認して超概算を打診する

**一言でいうと：現場担当者→決済担当者の順で確認し、両者の認識が一致した状態で超概算を提示する。**

> **このセクションは Step 1〜3 の流れの概要です。**
> 超概算を実際に打診する際の具体的な内容（金額の伝え方・前提条件・予算超過時の調整など）は、
> 「超概算：【対客】超概算内容の打診」で詳しく解説しています。

#### Step 1：現場担当者に予算を確認する

まず日常的に接触している現場担当者から、予算の感触を確認します。

```
確認すること：
  ・予算ステータス（配分済み・申請中・未定）
  ・おおよその規模感（「○千万円台」程度でOK）
  ・決済担当者は誰か（予算を承認できる人）
  ・現場担当者から決済担当者を紹介または予算に関する詳しいヒアリングの打ち合わせに同席してもらえるか
```

注意点：現場担当者の「これくらいで大丈夫と思います」は、決済担当者の合意とは別物です。
ここで満足せず、必ずStep 2に進みます。

#### Step 2：決済担当者の認識を確認する

現場担当者から得た情報を、決済担当者に直接確認します。

```
確認すること：
  ・現場担当者から聞いた予算感は正しいか
  ・予算の決定権は誰にあるか
  ・何が決め手になって発注するかを確認する
    （価格だけか？ノウハウ・実績・体制なども評価軸か？）
```

現場担当者が「大丈夫」と言っていても、決済担当者と認識がずれていることがよくあります。
このステップは、**後からの「白紙になった」を防ぐための最重要確認**です。

#### Step 3：決済担当者に超概算を打診する

Step 1・2で把握した予算の範囲に収まる超概算を、現場担当者・決済担当者に提示します。

```
打診の構成：
  ① 現時点でわかる超概算の上限を提示
  ② なぜその金額か（前提条件・不確定要素の説明）
  ③ 今後のスケジュール（いつ正式見積もりが出るか）
  ④ 予算に収まらない場合の選択肢
    （機能を絞る・フェーズを分ける）
```

## まとめとネクストアクション

### 3つの重要ポイント

1. **超概算より先に予算を確認する。「予算→超概算」の順が絶対**
   予算を知らずに出した超概算は修正が前提になる。
   予算の範囲内で「何ができるか」を提示するのが正しい超概算の組み立て方。

2. **現場担当者の「大丈夫」を信用しすぎない。決済担当者への直接確認が必須**
   現場担当者と決済担当者の認識はずれていることが多い。
   3ステップの最重要は Step 2——決済担当者の認識を直接確認すること。

3. **予算の確認と同時に「発注の決め手」も確認する**
   価格だけが発注の決定項目とは限らない。「価格以外で重視されることはありますか？」の一問で、自社が勝てる土俵（実績・体制・ノウハウ）を早期に把握できる。
   相見積もりに限らず、意思決定の軸を初期段階で把握しておくことがPMの役割。
