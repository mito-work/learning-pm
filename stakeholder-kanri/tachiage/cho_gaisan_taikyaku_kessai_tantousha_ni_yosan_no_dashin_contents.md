# ステークホルダー管理 > 立ち上げ

## 超概算：【対客】決済担当者に予算の打診

---

## 導入

### このスキルを身につけると、何が変わるか

「予算はいくらですか？と聞くのは失礼な気がして、聞けなかった」
「こちらで見積もりを出したら予算オーバーで、一から作り直しになった」
「担当者はOKと言っていたのに、上司に通したら白紙になった」——

多くのPMが超概算の場面でつまずく原因は、「予算を聞かないまま見積もりを出す」ことです。
顧客の予算を知らずに作った超概算は、予算オーバーになることが多く、修正に時間を取られます。
このスキルは、**顧客の予算を正しい順序で確認し、決済担当者に超概算を打診するまでの一連の流れ**を身につける技術です。

このスキルを学ぶことで：
- 「予算を聞く」ことへの心理的な壁がなくなる
- 顧客の予算ステータス（決まっているか・これからかを）見極められる
- 予算の範囲内で超概算を組み立てる手順が身につく
- 担当者と決済担当者の認識のズレを構造的に防げる

---

## 学習目標

このテキストを読み終えると、以下ができるようになります。

1. **なぜ予算を最初に確認しなければいけないかを説明し、顧客に自然に聞ける**
2. **顧客の「予算ステータス」を見極め、状況に応じた対応ができる**
3. **3ステップの手順で予算を確認し、決済担当者に超概算を打診できる**

## 本編

---

### Section 1：「予算を聞く」ことへの心理的な壁を乗り越える

**一言でいうと：予算を聞けないのは失礼だからではない。聞く理由が整理できていないからだ。**

多くのPMが予算を聞けない理由は「失礼かもしれない」という感情です。
しかし実際には、**予算を聞かない方が顧客にとっても不利益**になります。

```
予算を聞かずに超概算を出した場合：

  PM：「超概算として○○○○万円です」
  顧客：「うちの予算は○○○万円だったので無理です」
  PM：「そうでしたか…では作り直します」
  ↓
  ・双方の時間を無駄にする
  ・顧客は「この会社は私たちの状況を理解していない」と感じる
  ・信頼が下がる
```

**予算を聞くことは、顧客の状況に合わせた提案をするための必須情報収集です。**

#### 予算を聞くときの3つの切り口

「予算はいくらですか？」だけでは聞きにくい場面でも、以下の問いに変換すると答えてもらいやすくなります。

```
① 投資規模の確認
  「今回のシステム化に向けて、どのくらいの規模を
   ご想定されていますか？」

② 費用対効果の確認
  「このシステムを導入することで、どのような効果・
   リターンを期待されていますか？
   その効果に対して、どのくらいの投資がふさわしいと
   お考えですか？」

③ リスク・痛みの確認
  「現状のままでいると、どのようなリスクや
   コストが発生しますか？
   そのリスクを解消するために、どのくらいの
   コストが許容できますか？」
```

「予算の背景にある理由」がわかれば、予算は自然に引き出せます。
顧客が「なぜそのコストをかけたいのか」を自分の言葉で語ったとき、予算は情報として出てきます。

---

### Section 2：顧客の「予算ステータス」を見極める

**一言でいうと：「予算が決まっている」と「まだ決まっていない」は、対応が全く違う。最初にどちらかを確認する。**

超概算の打診に入る前に、顧客の予算がどの段階にあるかを確認します。

| ステータス | 意味 | 対応方針 |
|---------|-----|---------|
| **予算配分済み** | 承認された予算がすでに配分されている | その予算に収まる超概算を作る。上振れは絶対NG |
| **来期予算を申請中** | まだ予算承認前で、これから申請する | 超概算を根拠に予算申請を支援するイメージで進める |
| **検討段階・未定** | どのくらいかかるか知りたい段階 | 規模感を示しながら、予算確保に向けた動きを促す |

#### 予算ステータスの確認方法

```
「この案件はすでに予算のご用意がある状態でしょうか？
 それとも、今回のお話を踏まえてこれから予算を
 確保していく段階でしょうか？」
```

この一問で、どちらのステータスかがほぼわかります。

#### 「予算配分済み」の場合の重要ルール

**超概算は予算を上回ってはいけません。**

```
正しい考え方：予算 → 超概算（の順）

  顧客の予算が5,000万円と決まっている
  ↓
  超概算は5,000万円の範囲内で組み立てる
  ↓
  「5,000万円で何ができるか」を提示するのがPMの仕事

間違った考え方：超概算 → 予算確認（の順）

  ・「とりあえず見積もって、後で調整する」
  ・予算を聞かずに出した概算が予算を超えていた
  ・「削ってほしい」という交渉になる
  → 顧客との関係が交渉・削減モードになる
```

### Section 3：3ステップで予算を確認して超概算を打診する

**一言でいうと：現場担当者→決済担当者の順で確認し、両者の認識が一致した状態で超概算を提示する。**

#### Step 1：現場担当者に予算を確認する

まず日常的に接触している現場担当者から、予算の感触を確認します。

```
確認すること：
  ・予算ステータス（配分済み・申請中・未定）
  ・おおよその規模感（「○千万円台」程度でOK）
  ・決済担当者は誰か（予算を承認できる人）
  ・決済担当者に同席・紹介してもらえるか
```

注意点：現場担当者の「これくらいで大丈夫と思います」は、決済担当者の合意とは別物です。
ここで満足せず、必ずStep 2に進みます。

#### Step 2：決済担当者の認識を確認する

現場担当者から得た情報を、決済担当者に直接確認します。

```
確認すること：
  ・現場担当者から聞いた予算感は正しいか
  ・予算の決定権は誰にあるか
  ・何が決め手になって発注するかを確認する
    （価格だけか？ノウハウ・実績・体制なども評価軸か？）
```

現場担当者が「大丈夫」と言っていても、決済担当者と認識がずれていることがよくあります。
このステップは、**後からの「白紙になった」を防ぐための最重要確認**です。

#### Step 3：決済担当者に超概算を打診する

Step 1・2で把握した予算の範囲に収まる超概算を、決済担当者に提示します。

```
打診の構成：
  ① 現時点でわかる超概算の範囲（幅で提示）
  ② なぜその金額か（前提条件・不確定要素の説明）
  ③ 今後のスケジュール（いつ正式見積もりが出るか）
  ④ 予算に収まらない場合の選択肢
    （機能を絞る・フェーズを分ける）
```

#### 超概算が予算に収まらない場合の調整

予算の「リミットライン」に収まらないときは、削る前に調整の方向性を確認します。

```
リミットライン超過時の確認：

「現在の要件でお出しした超概算が○○○○万円になります。
 ご予算の○○○万円に収めるには、いくつかご相談があります。

 ① 機能を絞る
   優先度の低い機能を今回のスコープから外すと、
   ○○○万円程度に収まる見通しです。

 ② フェーズを分ける
   全機能を2フェーズに分けると、第1フェーズの
   初期投資を○○○万円に抑えられます。

 どちらのアプローチが貴社のご要望に合いますか？」
```

「削る」ではなく「優先順位をつける」という表現が、顧客の受け取り方を変えます。

---

### Section 4：予算を教えてもらえない場合の対処

**一言でいうと：「教えてもらえない」は実はほとんどない。本当に決まっていないケースの見極めが重要。**

実務上、顧客が予算を「教えない」ケースはあまり多くありません。
多くの場合は以下のどちらかです。

| パターン | 見分け方 | 対処 |
|--------|---------|-----|
| **本当に未定** | 「まだ予算申請前で」「来期の話で」という発言がある | 超概算を根拠に予算申請を支援する。「この規模感であれば○○○万円〜○○○万円の予算を申請されることをお勧めします」 |
| **聞かれるまで言わない** | 検討段階なのに「予算は…」とはぐらかす | Section 1 の「費用対効果・リスク」の切り口で聞き直す。「このシステムで解決したい課題にはどのくらいの価値がありますか？」 |

#### 教えてもらえないときに聞き直す言葉

```
「具体的な金額でなくて構いません。
 ○千万円台なのか、○億円台なのか、
 規模感だけでも教えていただけますか？

 その情報があると、私たちが提案できる内容の
 方向性が決まります。お互いの時間を
 無駄にしないためにも、ぜひ教えてください。」
```

---

### Section 5：相見積もりへの向き合い方

**一言でいうと：相見積もりは「価格競争に巻き込まれるシグナル」。金額以外の価値を早い段階で示す。**

顧客から「他社にも見積もりを取っています」と言われたとき、それは価格だけで比較されるリスクのサインです。

```
相見積もりが示すもの：
  ・「あなたたちを信頼して任せる」ではなく
    「複数の選択肢で比較したい」という状態
  ・価格が主要な決定項目になっている可能性が高い
```

#### 相見積もりへの対処：金額以外の決定項目を引き出す

```
確認すべき問い：
  「価格以外で、発注先を選ぶ際に
   重視されていることはありますか？

   たとえば、実績・ノウハウ・体制・
   コミュニケーションのやりやすさなど、
   御社のプロジェクトが成功するために
   重要な要素は何でしょうか？」
```

この問いに答えてもらうことで、「価格だけでは測れない価値」の軸が生まれます。
その軸で自社が優位であれば、価格競争から外れた提案ができます。

#### 相見積もりへの対応方針

自社に技術力・ノウハウの強みがある場合、以下の姿勢を明示することも選択肢の一つです。

```
「私どもは、価格を競り合う形ではなく、
 価値でお選びいただける形での提案を
 大切にしています。

 もし価格だけでのご比較であれば、
 私どもの提案スタイルと合わない可能性があります。

 御社のプロジェクトを成功させるために
 必要なことを一緒に考えていただける場であれば、
 ぜひご提案させてください。」
```

## まとめとネクストアクション

### 3つの重要ポイント

1. **超概算より先に予算を確認する。「予算→超概算」の順が絶対**
   予算を知らずに出した超概算は修正が前提になる。
   予算の範囲内で「何ができるか」を提示するのが正しい超概算の組み立て方。

2. **現場担当者の「大丈夫」を信用しすぎない。決済担当者への直接確認が必須**
   現場担当者と決済担当者の認識はずれていることが多い。
   3ステップの最重要は Step 2——決済担当者の認識を直接確認すること。

3. **相見積もりには「金額以外の決定項目」を引き出すことで対抗する**
   価格競争に乗ると信頼ではなく価格で選ばれる状態になる。
   自社が勝てる土俵（ノウハウ・実績・体制）に話を持っていくのがPMの役割。
