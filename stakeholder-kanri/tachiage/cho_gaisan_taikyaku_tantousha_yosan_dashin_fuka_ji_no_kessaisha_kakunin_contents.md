# ステークホルダー管理 > 立ち上げ

## 超概算：【対客】担当者予算打診不可時の決済者確認

---

## 導入

### このスキルを身につけると、何が変わるか

「担当者に予算の話をしたいと言ったら、『上には通せない』と断られた」
「誰が最終的に承認するのかわからないまま、超概算を提出してしまった」
「担当者はOKと言っていたのに、後から上司に却下されてプロジェクトが白紙になった」——

「決済者に直接話すべき」とわかっていても、担当者がブロックするケースは多くあります。
このスキルは、その壁を壊すのではなく、**担当者を「味方」にして決済者へのルートを開く**技術です。

このスキルを学ぶことで：
- 担当者を通じて決済者を確認する具体的な質問ができる
- 担当者のメンツを守りながら、上位者への橋渡しを依頼できる
- 決済者に直接会えない場合でも、承認の記録を残す方法がわかる
- 「誰も承認していない」まま進むリスクを回避できる

---

## 学習目標

このテキストを読み終えると、以下ができるようになります。

1. **なぜ担当者が「予算打診不可」になるのか、その背景を説明できる**
2. **担当者を通じて決済者を確認するための質問を、具体的に実践できる**
3. **決済者に直接会えない場合でも、プロジェクトを安全に進めるための記録を取れる**

---

## 本編

---

### Section 1：なぜ「担当者予算打診不可」が起きるのか

**一言でいうと：担当者にも事情がある。その背景を理解してから動く。**

「上には通せません」「まだそのタイミングではない」という反応には、いくつかのパターンがあります。

| パターン | 背景 | PMが取るべき対応 |
|--------|-----|--------------|
| **権限がない** | 担当者が予算の議論に参加できる立場ではない | 「どなたがご判断されますか？」と確認する |
| **社内稟議がまだ** | 上司への報告タイミングが決まっていない | 「いつ頃ご報告の予定ですか？」と聞く |
| **組織の政治** | 上司と担当者の関係が複雑で、上司への直接アクセスが難しい | 担当者を通じた「間接的な承認」を取る |
| **まだ概算を出す段階ではないと思っている** | 担当者が超概算の目的を理解していない | 「なぜ今の段階で概算が必要か」を説明する |

**最初にやるべきことは、担当者を「敵」と見なさないことです。**
担当者には担当者の立場があり、上司との関係や社内ルールがあります。
その背景を理解した上で、担当者を「橋渡し役」にするアプローチが最も効果的です。

---

### Section 2：担当者を通じて「決済者が誰か」を確認する

**一言でいうと：「誰が承認するか」だけは、担当者を通じて最初に確認する。**

決済者に直接会えなくても、「誰が最終的に承認するのか」は把握しておく必要があります。
これがわからないまま進むと、後から「その人は聞いていない」という状況が必ず起きます。

#### 担当者への確認の仕方

「決済者を教えてください」という直接的な聞き方は、担当者によっては「社内のことを探っている」と感じさせることがあります。
代わりに、**プロジェクトを進めるために必要な情報として確認する**という文脈で聞きます。

```
確認の例（NG）：
「最終的な承認者は誰ですか？」
→ 「なぜそれを聞くのか」と警戒される可能性がある

確認の例（OK）：
「今回の概算をご説明した後、社内でのご判断はどのような流れで進みますか？
 どなたのご承認が必要になりますか？
 準備できることがあれば、事前にお伝えしたいと思いまして。」
→ 「あなたの社内手続きを支援したい」という文脈になる
```

この聞き方のポイントは、「承認者を知りたい」ではなく「あなたの社内説明を助けたい」というスタンスです。

---

### Section 3：担当者を「味方」にする技術

**一言でいうと：担当者が社内で説明しやすい材料を作ってあげる。**

担当者が「上に通せない」と言う理由の多くは、「上司に説明できる自信がない」ことにあります。
PMが担当者の「社内説明の準備」を手伝うことで、担当者は自然と橋渡し役になります。

#### 担当者が上司に説明しやすい資料を作る

```
担当者への提案：
「上司の方へのご報告に使っていただける、簡単な説明資料を
 1〜2ページで作成しましょうか？
 金額の根拠・前提条件・次のステップをまとめた資料があれば、
 社内でのご説明がしやすくなると思います。」
```

この提案には2つの効果があります。
- 担当者の負担を減らす（担当者に感謝される）
- PMが作成した資料が上司に届く（決済者への間接的なアプローチ）

#### 資料に含めるべき内容

| 内容 | 目的 |
|-----|-----|
| **プロジェクトの目的・解決する課題** | 「なぜやるか」を上司が理解できるようにする |
| **概算金額（幅・前提条件）** | 「いくらかかるか」を正確に伝える |
| **投資対効果（しない場合のリスク）** | 「やる価値があるか」を判断できるようにする |
| **次のステップと確認事項** | 「何を決めてほしいか」を明確にする |

「上司が判断するために必要な情報」を担当者と一緒に整理することで、担当者は「準備万端で上司に報告できる」という安心感を得ます。

---

### Section 4：どうしても決済者に会えない場合の対処

**一言でいうと：直接会えなくても「承認した記録」は必ず取る。**

担当者が「上には通せない」の姿勢を変えない場合でも、プロジェクトを進めるための最低限の確認は必要です。

#### ① 「担当者の承認」を書面で残す

決済者に会えない場合、担当者の合意を書面で残すことが次善策になります。

```
メールの例：
「本日ご説明した超概算の内容（金額：〇〇万円〜〇〇万円、前提：〇〇）について、
 担当者の〇〇様にご確認いただきましたが、この理解で相違ないでしょうか。
 社内での最終承認のタイミングについても、追ってご連絡いただけますと幸いです。」
```

「担当者がOKした記録」を取っておくことで、後から「聞いていない」が起きた場合の根拠になります。

#### ② プロジェクトを進めるリスクを伝える

「誰も承認していない状態でプロジェクトを進めることのリスク」を、担当者に正直に伝えます。

```
伝え方の例：
「予算規模の合意がないまま次のフェーズに進むと、
 後から『想定と違う』という状況になりやすいです。
 PMとして、最低限、金額の目安についてご担当部門の上位の方に
 ご認識いただけると、双方にとって安心です。
 どのような形であればご調整いただけますか？」
```

「リスクを一緒に回避したい」というスタンスで伝えることで、担当者に「PMは自分たちの味方だ」という印象を持ってもらえます。

#### ③ 「承認タイミング」だけは合意する

直接の承認が難しい場合でも、「いつ誰が承認するか」だけは確認します。

```
確認の例：
「今すぐのご判断は難しいと理解しています。
 ○月○日の取締役会でご報告いただける予定でしょうか？
 その際に使えるご説明資料を事前にお送りします。」
```

「いつ・誰が・どこで承認するか」が見えているだけで、PMはプロジェクトの計画が立てられます。

---

### Section 5：「担当者とPMの関係」が鍵になる

**一言でいうと：担当者がPMを信頼しているほど、決済者への橋渡しはスムーズになる。**

担当者が「上に通せない」と言うとき、それはPMへの不信感が原因のこともあります。
「この人に予算の話をしたら、後で自分が困ることにならないか」という不安です。

#### 担当者の信頼を得るための行動

```
✅ やること：
・担当者の発言を議事録に正確に残す（「あなたの言葉を尊重している」という示し）
・担当者が社内で困らないように、共有する情報の粒度を一緒に決める
・「この金額は私が担当者さんを通して確認しました」という言い方をする

❌ やってはいけないこと：
・担当者を飛ばして上司に直接連絡する（担当者のメンツが潰れる）
・「担当者には話した」という既成事実を使って決済者に迫る
・「あなたには決める権限がないから」という言い方をする
```

担当者が「PMは自分の味方だ」と感じていれば、上司への橋渡しは自発的に行われます。
**担当者との関係構築が、決済者へのアクセスを開く鍵です。**

## まとめとネクストアクション

### 3つの重要ポイント

1. **「担当者予算打診不可」には背景がある。まず理由を理解する**
   権限・稟議タイミング・組織の政治・超概算の目的理解不足——理由によって対応が変わる。
   担当者を「壁」ではなく「事情を抱えた協力者候補」として見ることが出発点。

2. **「誰が承認するか」だけは必ず確認する。プロジェクトの進め方で直接聞かず、「社内手続きを支援したい」文脈で聞く**
   「どなたのご承認が必要ですか？準備できることがあればお伝えしたいので」という一言が、
   担当者の警戒を解く。

3. **担当者が「社内で説明しやすい状態」を作ってあげることが、決済者へのルートを開く**
   1〜2ページの社内説明資料を担当者と一緒に準備する。
   担当者の負担を減らすことで、担当者は自発的に橋渡し役になる。
